Ниже представлен агрегированный отчёт, который объединяет все предыдущие обсуждения и даёт целостную картину того, **как самостоятельно построить Deep Research‑инструмент на Java**. Акцент сделан на конкретные инструменты, подходы и перечень того, что потребуется реализовать.

## 1. Целевая архитектура

Вне зависимости от выбранных библиотек, ваше решение должно закрывать следующий конвейер:

1.  **Обход и чтение** – рекурсивный обход локальной папки с репозиториями и документами, фильтрация файлов, извлечение текстового содержимого.
2.  **Чанкинг** – разбиение документов на фрагменты, оптимизированные под последующий семантический поиск и генеративный ответ.
3.  **Эмбеддинги и индексация** – преобразование чанков в векторные представления и сохранение их в векторном хранилище.
4.  **Агентный исследовательский цикл** – итеративное планирование, поиск, оценка релевантности, уточнение запросов, накопление контекста.
5.  **Генерация финального отчёта** – синтез структурированного отчёта с цитатами и метаданными источников.

## 2. Инструменты и подходы для Java‑реализации

### 🧱 Базовый фреймворк и интеграции

| Компонент | Рекомендуемый инструмент | Зачем нужен |
| :--- | :--- | :--- |
| **Языковая модель (LLM)** | **Ollama** + модели `mistral`, `llama3`, `deepseek-coder` | Локальное исполнение, конфиденциальность данных, отсутствие платы за токены. Spring AI поддерживает `OllamaChatModel` из коробки. |
| **RAG‑фреймворк** | **Spring AI** (текущая стабильная версия 1.0.0+, milestone 1.1.0-M4 для Recursive Advisors) | Предоставляет `ChatClient`, абстракции `DocumentReader`, `VectorStore`, `EmbeddingModel`, ETL‑конвейер. Упрощает интеграцию с десятками хранилищ и моделей. |
| **Векторное хранилище** | **PGVector** (расширение PostgreSQL) или **Qdrant** (через Docker) | PGVector хорош, если у вас уже есть PostgreSQL. Qdrant — легковесный, производительный, с удобным REST API. Оба поддерживаются Spring AI через `VectorStore` интерфейс. |
| **Эмбеддинги** | **OllamaEmbeddingModel** (модель `nomic-embed-text`) | Полностью локальные эмбеддинги, хорошо работающие с кодом и техническим текстом. |
| **Извлечение текста** | **Apache Tika** (через `TikaDocumentReader` из Spring AI) или чистый **Apache PDFBox** для сложных PDF | Tika «всеядна»: PDF, DOCX, HTML. PDFBox даёт больше контроля над таблицами и структурой. |
| **MCP‑сервер файловой системы** | **@modelcontextprotocol/server-filesystem** (Node.js‑пакет, запускается как sidecar) | Альтернатива прямому обходу папок. Позволяет агенту динамически исследовать файловую систему, читать и искать файлы, не индексируя всё заранее. Интегрируется через Spring AI `McpClient`. |

### 🧠 Ключевые фреймворки для агентного цикла

Здесь лежит главная сложность — «глубокое исследование» требует многошагового агента. Есть три зрелых подхода на Java:

#### 2.1 LangGraph4j
- **Что это**: Прямой порт концепции LangGraph (Python) на Java. Позволяет описывать рабочие процессы как граф состояний.
- **Сильные стороны**: Полный контроль над ветвлением и состоянием. Идеален для сложной логики «план → сбор → анализ → перепланирование».
- **Как применить**: Определяете вершины графа (например, `PlanNode`, `SearchNode`, `ReflectNode`, `FinalizeNode`) и переходы между ними. Внутри каждой вершины вызываете `ChatClient` или `VectorStore`.
- **Интеграция**: Работает поверх `langchain4j`, но легко дружит и со `Spring AI` через ручную адаптацию (или наоборот).

#### 2.2 Spring AI Alibaba Agent Framework
- **Что это**: Часть проекта Spring AI Alibaba, предоставляющая декларативных агентов верхнего уровня: `SequentialAgent`, `ParallelAgent`, `LoopAgent`, `RoutingAgent`.
- **Сильные стороны**: Можно собрать сложного агента из готовых блоков, описывая их в конфигурации. Включает **Spring AI Alibaba Graph** — движок для длительных агентных процессов с контролем состояний и промежуточным сохранением прогресса.
- **Пример**: `LoopAgent` автоматически повторяет вызов LLM, пока не будет достигнуто условие завершения. Это почти готовая основа для цикла Deep Research.

#### 2.3 Recursive Advisors (Spring AI)
- **Что это**: Новый API в Spring AI (с версии 1.1.0-M4), позволяющий обернуть вызов `ChatClient` в рекурсивный цикл с проверкой качества.
- **Сильные стороны**: Самый простой способ добавить итеративность без внешних фреймворков. Advisors могут анализировать ответ LLM и принимать решение о дополнительном витке.
- **Типовой сценарий**: `SearchAdvisor` → `ReflectionAdvisor` → `FinalAnswerAdvisor`. Если отражение показывает, что контекста недостаточно, инициируется новый поиск с уточнённым запросом.

> **Рекомендация**: Начните с **Spring AI Alibaba LoopAgent** или **Recursive Advisors**, как с наиболее простых в освоении. Если логика усложнится, мигрируйте на **LangGraph4j**.

## 3. Что именно потребуется реализовать

Ниже — детальный список модулей, которые вам предстоит написать, даже при использовании перечисленных фреймворков.

### 3.1 Модуль обхода и чтения документов (FileSystem Crawler)
- **Задача**: рекурсивно обойти указанную корневую папку, отобрать файлы нужных расширений (`.java`, `.py`, `.md`, `.yaml`, `.pdf`, `.docx`, `.txt`), игнорируя бинарные файлы и директории типа `node_modules`, `.git`, `target`.
- **Реализация**:
    - Написать `FileSystemCrawler` с использованием `java.nio.file.Files.walkFileTree()`.
    - Интегрировать `TikaDocumentReader` для преобразования файлов в `List<Document>` Spring AI.
    - Для Java‑файлов можно добавить поверхностный парсер (например, `StringUtils.substringBetween`), чтобы извлекать только комментарии Javadoc и сигнатуры методов, но это опционально.
- **Результат**: поток (или коллекция) объектов `Document` с заполненными полями `content` и `metadata` (путь, имя файла, дата изменения).

### 3.2 Умный чанкинг (Smart Splitting)
- **Задача**: нарезать документы на фрагменты, подходящие для эмбеддингов (обычно 256–512 токенов) с перекрытием.
- **Особенность**: для исходного кода стандартный `TokenTextSplitter` может разорвать метод или класс. Желательно реализовать кастомный `JavaCodeSplitter`, который разбивает по границам классов и методов (можно через простое регулярное выражение типа `(\s*\/\*\*[\s\S]*?\*\/\s*)?\s*(public|private|protected)?\s*(static|final)?\s*\w+[\s\S]*?\{`).
- **Инструменты Spring AI**: `TokenTextSplitter`, `RegexSplitter` или реализация собственного `TextSplitter`.
- **Результат**: для каждого исходного документа — список чанков с метаданными (в каком файле находился, какой фрагмент кода).

### 3.3 Конвейер эмбеддингов и индексации
- **Задача**: преобразовать чанки в векторы и сохранить в хранилище.
- **Реализация**:
    - Использовать `OllamaEmbeddingModel` через `spring.ai.ollama.embedding.enabled=true`.
    - Настроить `VectorStore` (например, `PgVectorStore` или `QdrantVectorStore`) как Spring Bean.
    - Создать `@Service`, который принимает `List<Document>`, вызывает `vectorStore.add(documents)` (внутри которого произойдёт вызов эмбеддингов).
- **Особенность**: при большом количестве файлов индексация должна быть асинхронной (например, с помощью `@Async` и `CompletableFuture`), чтобы не блокировать старт приложения.
- **Результат**: наполненное векторное хранилище, готовое к поиску.

### 3.4 Агентный цикл глубокого исследования
- **Задача**: реализовать итеративный процесс, который по исследовательскому вопросу пользователя:
    1.  Формулирует начальный план (например, разбивает тему на подзадачи).
    2.  Выполняет поиск по векторному хранилищу для каждой подзадачи.
    3.  Оценивает, достаточно ли информации. Если нет — генерирует уточняющие вопросы и снова ищет.
    4.  Накапливает контекст и в итоге передаёт всё финальному генератору отчёта.
- **Варианты реализации**:
    - *С помощью LangGraph4j*: граф с узлами `Plan`, `Search`, `Evaluate`, `Finalize`. Состояние хранит накопленный контекст и историю.
    - *С помощью LoopAgent*: петля, где на каждой итерации агент решает, завершать ли работу, или добавить новый запрос.
    - *С помощью Recursive Advisors*: цепочка advisor'ов, которая повторяется, пока `ReflectionAdvisor` не решит, что ответ готов.
- **Промпт‑дизайн**: особое внимание следует уделить промптам для планировщика и оценщика. Планировщик должен понимать, что анализируются именно репозитории с тестированием LLM и CLI‑приложениями. Оценщик должен проверять релевантность найденных чанков, отбрасывать устаревшие или неинформативные.
- **Результат**: накопленный структурированный контекст (например, Map<подзадача, список цитат>).

### 3.5 Генератор финального отчёта
- **Задача**: из накопленного контекста создать структурированный Markdown‑отчёт (или PDF) с разделами: «Обзор проектов», «Подходы к тестированию LLM», «Инструменты CLI‑тестирования», «Ключевые идеи для реализации на Java», «Сравнительная таблица» и т.п.
- **Реализация**: финальный вызов `ChatClient` с очень детальным системным промптом, который диктует структуру отчёта, требует указывать ссылки на конкретные файлы (которые у вас есть в метаданных) и оформлять всё в Markdown.
- **Пост‑обработка**: при необходимости конвертировать Markdown в PDF (например, с помощью библиотеки `flexmark` + `openhtmltopdf`).

### 3.6 Опционально: MCP‑сервер для динамического доступа
- **Когда нужно**: если вы не хотите предварительно индексировать всё хранилище, а предпочитаете, чтобы агент «сам ходил» по папкам в процессе исследования.
- **Настройка**:
    - Запустить `@modelcontextprotocol/server-filesystem` как отдельный процесс (через `npx` или Docker), указав корень вашей папки.
    - В Spring AI настроить `McpClient`, который будет предоставлять инструменты `list_directory`, `read_file`.
    - Агент (через function calling) сможет вызвать эти инструменты, чтобы динамически исследовать структуру и читать файлы.
- **Преимущество**: не теряется время на полную индексацию, но каждый исследовательский цикл будет медленнее из-за реального чтения файлов.

## 4. Поэтапный план реализации

| Этап | Содержание работ | Ожидаемая длительность (1 разраб.) | Ключевые технологии |
| :--- | :--- | :--- | :--- |
| **1. Прототип RAG** | Простой поиск по папке: обход, Tika, чанкинг, индексация в PGVector, вопрос-ответ через Ollama. Без агента. | 2–3 недели | Spring AI, Tika, PGVector, Ollama |
| **2. Агентный цикл** | Реализация LoopAgent или Recursive Advisors для итеративного исследования. Планировщик, оценщик, уточнение. | 3–4 недели | Spring AI Alibaba / Recursive Advisors, LangGraph4j (опционально) |
| **3. Генератор отчёта** | Мощный промпт для финального синтеза, экспорт в Markdown/PDF. | 1–2 недели | ChatClient, flexmark |
| **4. Умный чанкинг кода** | Кастомные сплиттеры для Java/Python. Улучшение качества поиска. | 1–2 недели | Регулярные выражения, TextSplitter API |
| **5. MCP‑интеграция** (опционально) | Добавление динамического доступа к ФС для гибкости. | 1 неделя | MCP Client, server-filesystem |
| **6. Оптимизация** | Асинхронная индексация, инкрементальное обновление, кэширование эмбеддингов. | 2–3 недели | @Async, Spring Cache |

## 5. Критические нюансы, которые нельзя упустить

- **Промпты — сердце агента**. Даже самый совершенный граф не даст результата, если промпты для планирования и оценки не будут тщательно выверены на ваших данных. Промпт должен явно требовать искать подходы, инструменты и идеи для переноса на Java.
- **Качество чанкинга кода**. Если разбить исходники «по токенам», метод может быть разорван посередине, и поиск не найдёт его по ключевым словам. Инвестируйте время в `JavaCodeSplitter` — это окупится точностью ответов.
- **Локальная модель Ollama**. Модели типа `mistral` или `llama3` хорошо справляются с генерацией кода и текстов, но для сложного планирования может потребоваться более мощная модель (если позволит железо). Начните с 7B-модели, но будьте готовы к экспериментам.
- **Производительность эмбеддингов**. `nomic-embed-text` — хороший старт, но можно рассмотреть специализированные кодо‑эмбеддеры на Ollama, если качество семантического поиска по коду окажется недостаточным.

## 6. Итоговый вывод

Самостоятельная разработка Deep Research‑инструмента на стеке Java + Spring AI + Ollama **вполне реализуема**, но требует последовательного движения от простого RAG‑прототипа к итеративному агенту.

- **Стартовать** рекомендуется с **Spring AI + PGVector + Recursive Advisors** (или Spring AI Alibaba LoopAgent).
- **Для сложной оркестрации** по мере роста требований переходить на **LangGraph4j**.
- **MCP‑сервер** использовать, если важнее гибкость динамического исследования, а не производительность предварительной индексации.

Такой путь даст вам полный контроль над логикой анализа, изначально заточенную под вашу Java‑экосистему архитектуру и бесценный опыт создания агентных систем, который вы сможете переиспользовать в будущих проектах.
