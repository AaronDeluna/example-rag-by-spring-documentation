### Определение задачи

Анализ множества локальных репозиториев с кодом и PDF-документов, а затем подготовки структурированной базы подходов и идей — я вижу два наиболее сильных подхода. Оба способны дать глубокий исследовательский результат, но различаются сложностью настройки и гибкостью.

---

### 🥇 Вариант 1: GPT Researcher — готовый RAG-ассистент с индексацией локальной папки

**Почему он подходит:**  
GPT Researcher умеет индексировать все содержимое заданной папки (включая вложенные директории) — код в `.py`, `.java`, `.md`, `.txt`, а также PDF, DOCX, электронные таблицы и другие форматы. По индексу выполняется семантический поиск, на основе которого генерируется отчёт. Для вас это означает: один раз проиндексировать папку со всеми репозиториями, а затем задать исследовательский запрос вида «Систематизируй подходы, инструменты и архитектурные идеи из этих проектов для создания аналогичного решения на Java».

#### 🛠️ Как настроить и запустить:

1. **Клонируйте репозиторий и подготовьте окружение:**
   ```bash
   git clone https://github.com/assafelovic/gpt-researcher.git
   cd gpt-researcher
   cp .env.example .env
   ```

2. **Настройте `.env` для локального анализа:**
    *   Чтобы всё работало полностью локально (включая эмбеддинги и LLM), используйте Ollama:
     ```ini
     # LLM для генерации отчёта
     FAST_LLM=ollama:mistral
     SMART_LLM=ollama:mistral
     # Модель для эмбеддингов при индексации файлов
     EMBEDDING_PROVIDER=ollama:nomic-embed-text
     OLLAMA_BASE_URL=http://localhost:11434
     ```
    *   Путь к папке с вашими репозиториями:
     ```ini
     DOC_PATH=/absolute/path/to/your/repositories_folder
     ```
    *   Отключите поиск в интернете, если он не нужен (оставьте только локальные документы). Это можно будет сделать через веб-интерфейс.

3. **Запустите приложение:**
   ```bash
   docker-compose up -d   # или python main.py для режима разработки
   ```
   Веб-интерфейс откроется на `http://localhost:8000`.

4. **Выполните задачу глубокого исследования:**
    *   В интерфейсе переключите источник данных 🔽 на **“My Documents”**.
    *   Включите режим **Deep Research** (рекурсивный многошаговый анализ).
    *   Введите исследовательский запрос, например:
   > Проанализируй все проекты в локальной папке. Определи основные подходы к тестированию LLM и CLI-приложений, используемые инструменты, архитектурные идеи. Сформируй структурированный отчёт с разбивкой по проектам и обобщением, пригодный для дальнейшей разработки комплексного Java-решения.

5. **Получите результат:**  
   GPT Researcher сгенерирует отчёт со ссылками на локальные файлы, сводными таблицами и ключевыми выводами. Отчёт можно экспортировать в PDF, DOCX или Markdown.

> **Важно:** При первом запуске будет происходить индексация всех файлов — это может занять время в зависимости от объёма данных и производительности оборудования. Модель эмбеддингов (например, `nomic-embed-text` в Ollama) должна быть предварительно загружена.

### 🥈 Вариант 2: Open Deep Research + MCP-сервер — гибкий агентный обход файлов

**Когда выбирать:** Если вам нужен более тонкий контроль над процессом — например, агент должен обходить каждую папку, читать README, искать ключевые файлы исходного кода, самостоятельно решать, на чём сфокусироваться. Этот подход использует LangGraph и Model Context Protocol (MCP) для динамического доступа к файловой системе без предварительной полной индексации.

#### 🛠️ Общая схема настройки:

1. **Разверните Open Deep Research:**  
   Следуя официальной инструкции, поднимите среду через Docker или `uv sync`. Убедитесь, что агент может использовать локальный LLM через Ollama.

2. **Подключите MCP-сервер файловой системы:**  
   Официальный сервер `@modelcontextprotocol/server-filesystem` предоставляет инструменты для навигации по директориям и чтения файлов.  
   Добавьте его в конфигурацию LangGraph агента:
   ```json
   {
     "mcpServers": {
       "filesystem": {
         "command": "npx",
         "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/repos"]
       }
     }
   }
   ```

3. **Создайте исследовательский граф (упрощённый пример):**
    *   **Планировщик** получает задачу («проанализируй все проекты») и составляет список подзадач: перечислить папки, для каждой прочитать README и ключевые файлы.
    *   **Сборщик** использует MCP-инструмент `list_directory`, затем `read_file` для каждого проекта. Результаты накапливаются.
    *   **Анализатор** прогоняет собранные описания через LLM и формирует итоговый структурированный отчёт.
        Такой граф можно описать на Python с использованием `langgraph`.

4. **Запустите исследование и получите отчёт.**  
   В отличие от GPT Researcher, здесь вы полностью контролируете формат отчёта и можете включить в него именно те аспекты, которые важны для Java-разработки.

---

### 💎 Сравнение и итоговая рекомендация

| Критерий | GPT Researcher | Open Deep Research + MCP |
| :--- | :--- | :--- |
| **Сложность запуска** | 👍 Легко (Docker, одна команда) | 👨‍💻 Высокая (нужно программировать граф) |
| **Работа с локальными файлами** | Автоиндексация папки (PDF, код, Markdown, Excel…) | Динамический обход и чтение через MCP |
| **Глубина анализа** | Готовый режим Deep Research | Полный контроль над логикой исследования |
| **Приватность** | Полностью локальная (Ollama) | Полностью локальная (Ollama и MCP) |
| **Готовность отчёта** | Структурированный отчёт с цитатами | Требует самостоятельного описания формата вывода |
| **Рекомендуется** | Для быстрого и комплексного решения задачи без разработки | Если нужна специфическая логика анализа или интеграция в существующий пайплайн на Java |
