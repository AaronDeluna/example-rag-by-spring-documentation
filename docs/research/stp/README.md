> Планируется сделать следующее: создать "систему технологического преимущества" или СТП. Ее смысл в том, чтобы собирать различную информацию в интернете по темам: разработка, тестирование, автоматизация тестирования, работа с ИИ. Всю информацию сохранять локально в виде Md файлов и анализировать. Цель анализа - следить за новостями в предметных областях, которые интересны, а так же выполнять Deep Research с помощью таких инструментов, как GPT Researcher. В конечном итоге это должно дать преимущество и улучшить качество выполняемых задач. А исходные данные можно по разному анализировать для того, чтобы генерировать новые идеи и решать производственные задачи.
> Проблема в том, что ожидается, что это будут несколько разных сервисов, поднимаемых на разных стенках и требуется проработать их архитектуру. Стоит ли для этого арендовать отдельную виртуальную машину или можно сделать все на обычном ноутбуке. Так же необходимо подумать над сохранением данных, бэкапами и над тем, как работать с изображениями.

### 🧩 Актуализированная архитектура (ключевые модули)

1. **`orchestrator`** – Java-координатор: расписания, приём команд от пользователя, запуск цепочек.
2. **`crawler`** – Crawl4AI + пул прокси – честная добыча чистого Markdown.
3. **`memory-mcp`** – индексация Markdown в SQLite, полнотекстовый поиск, доступ для других сервисов.
4. **`researcher`** – Deep Research (GPT Researcher / open-source аналог) – вызывается по запросу.
5. **`idea-agent`** (новый) – автономный «генератор идей»: анализирует накопленные данные, сам запускает `researcher` и формулирует гипотезы.
6. **`notifier`** – отправка дайджестов в Telegram и Макс.
7. **`vision-mcp`** – захват скриншотов и поиск по изображениям (на будущее, опционально).
8. **`backup-agent`** – регулярное резервное копирование.

Все компоненты работают независимо, общаются через REST, используют общее файловое хранилище.

## 📅 Пошаговый план (от простого к сложному)

### Этап 1. Инфраструктура и MVP сбора данных
**Цель:** получить конвейер «URL → чистый Markdown на диске», развёрнутый на VPS.

1. Выбрать VPS (4 ГБ ОЗУ, SSD ≥50 ГБ), установить Docker, Docker Compose.
2. Настроить WireGuard VPN на сервере для вашего безопасного доступа.
3. Создать структуру каталогов `/opt/stp/data/` (markdown, images, db, exports).
4. Поднять `crawler` (Crawl4AI) с подключением пула резидентных прокси.
5. Реализовать простейший `orchestrator` на Java (Spring Boot):
    - статический список источников (RSS, URL);
    - cron-задание: раз в час запрашивает Crawl4AI, получает Markdown;
    - добавляет YAML-фронтматтер (дата, источник, теги);
    - сохраняет в `data/markdown/theme/`.
6. Проверить цепочку на 2–3 источниках.

### Этап 2. Хранение и базовый поиск
**Цель:** превратить кучу файлов в индексированное хранилище с API.

7. Развернуть `memory-mcp`-сервер, который:
    - отслеживает новые `.md`-файлы в `data/markdown/`;
    - индексирует их в SQLite (полнотекстовый поиск + метаданные);
    - предоставляет REST-эндпоинты: `/search?q=keyword&from=...&tags=...`.
8. Настроить `backup-agent`:
    - ежедневный бэкап SQLite и `data/` в облачное S3-хранилище (Яндекс.Облако, Backblaze B2).

### Этап 3. Уведомления и первые дайджесты
**Цель:** регулярно доставлять пользователю агрегированную выжимку.

9. Создать `notifier` (Python/Go) с двумя коннекторами:
    - Telegram Bot (aiogram/pyrogram);
    - Мессенджер Макс (изучить API, реализовать адаптер).
10. В `orchestrator` добавить задачу «ежедневный дайджест»:
    - запрашивает `memory-mcp` за последние 24 часа;
    - формирует сводку по темам;
    - отправляет через `notifier`.
11. Реализовать в `orchestrator` приём простых команд из мессенджеров:
    - `/digest` – получить дайджест за сегодня;
    - `/search keyword` – поиск по хранилищу.

### Этап 4. Deep Research по запросу
**Цель:** проводить глубокое исследование по команде пользователя или по расписанию.

12. Развернуть `researcher` (GPT Researcher или аналог из списка Open Deep Research) в отдельном контейнере.
13. Настроить его на использование как веб-источников, так и вашего `memory-mcp` (через API).
14. Добавить в `orchestrator` метод запуска исследования:
    - по команде `/research тема` из Telegram/Макс;
    - по cron (например, раз в неделю по ключевым темам).
15. Результат сохраняется в `data/markdown/deep-research/` и приходит уведомлением.

### Этап 5. Автономный поиск идей (модуль `idea-agent`)
**Цель:** реализовать полную автономность – система сама находит перспективные темы и исследует их без участия человека.

16. Создать модуль `idea-agent` (Python, LangChain/LangChain4j, или аналог):
    - имеет доступ к `memory-mcp` (поиск по накопленным данным);
    - умеет вызывать `researcher` (запуск Deep Research);
    - может отправлять уведомления через `notifier`.
17. Реализовать два режима работы:
    - **Пассивный**: раз в сутки анализирует свежие новости, находит новые термины/тренды и генерирует **предложения** тем для исследования. Отправляет пользователю запрос: «Предлагаю исследовать: X. Запустить?»
    - **Автономный** (включается по желанию): без подтверждения запускает `researcher` по предложенной теме, сохраняет результат и уведомляет пользователя о готовности.
18. Интегрировать `idea-agent` с оркестратором: оркестратор лишь предоставляет ему API доступ к сервисам, но логика принятия решений живёт полностью внутри агента.

### Этап 6. Работа с изображениями (опционально сейчас, можно зафиксировать на потом)
**Цель:** сохранять скриншоты статей и уметь искать по ним.

19. Развернуть `vision-mcp` (AgenticVision) для:
    - автоматического снятия скриншотов при парсинге (если нужно);
    - индексации изображений в векторном виде (CLIP-эмбеддинги);
    - поиска «похожих скриншотов».
20. В Markdown-файлы добавлять ссылки на скриншоты, а `memory-mcp` – учитывать их при поиске.

## Дополнительно
- **agent-memory-mcp (v0.8.0)** — эволюционировавший MCP-сервер на Go, который из простого semantic-search инструмента превратился в «memory backbone» для инженерных агентов. Появились: local-only режим и reembed, hybrid retrieval с source-aware ranking, trust/freshness-метаданные, session close pipeline (автоматическое извлечение знаний из сессий), stewardship layer (обслуживание и очистка памяти), canonical knowledge + project bank, structure-aware RAG для Markdown и multi-hop recall. **Репозиторий:** `ipiton/agent-memory-mcp`.
- **NOUZ** — локальный MCP-сервер-посредник между Obsidian и ИИ‑агентами (Python). Превращает базу Markdown-заметок в структурированную память с графом, уровнями и сигналами дрейфа. Три режима: **LUCA** (граф и YAML-связи без эмбеддингов), **PRIZMA** (семантика: ядра, эталоны, авто-подсказки, кросс-доменные мосты), **NOVA** (автономная работа без человека). Принцип «сервер считает — человек решает». **Пакет:** `nouz-mcp` на PyPI.
