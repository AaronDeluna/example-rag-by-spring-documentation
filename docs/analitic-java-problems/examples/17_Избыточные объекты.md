# Избыточные объекты

**Категория:** Стиль кодирования (Clean Code)

**Описание:** Создание объектов, которые можно не создавать (например, `String` вместо `StringBuilder` в циклах).

**Инструменты:** PMD, SpotBugs

---

Вот пример, демонстрирующий проблему «Избыточные объекты» на Java.

---

### Корректный пример

Используется `StringBuilder` для конкатенации строк в цикле, что предотвращает создание множества промежуточных объектов `String`.

```java
public class CorrectStringBuilderUsage {
    public static String buildSentence(String[] words) {
        StringBuilder sb = new StringBuilder();
        for (String word : words) {
            sb.append(word).append(" ");
        }
        // Удаляем последний пробел
        if (sb.length() > 0) {
            sb.setLength(sb.length() - 1);
        }
        return sb.toString();
    }

    public static void main(String[] args) {
        String[] words = {"Java", "is", "great"};
        System.out.println(buildSentence(words)); // Java is great
    }
}
```

---

### Некорректный пример

В цикле каждый раз создаётся новый объект `String` через оператор `+`, что приводит к избыточному потреблению памяти и снижению производительности.

```java
public class IncorrectStringConcatenation {
    public static String buildSentence(String[] words) {
        String result = "";
        for (String word : words) {
            result = result + word + " ";  // Проблема: создаётся новый String на каждой итерации
        }
        return result.trim();
    }

    public static void main(String[] args) {
        String[] words = {"Java", "is", "great"};
        System.out.println(buildSentence(words)); // Java is great
    }
}
```

---

### Объяснение и выявление инструментом

**Почему некорректный пример плох:**
- В Java строки являются неизменяемыми (immutable). Каждая операция `result + word` создаёт новый объект `String` в куче, а старый объект остаётся на усмотрение сборщика мусора.
- В цикле с миллионом элементов это приведёт к созданию ~2 миллионов лишних объектов (промежуточные строки и строки с пробелом), что сильно замедлит выполнение и увеличит нагрузку на GC.
- Это нарушает принцип эффективного управления памятью и является антипаттерном «избыточное создание объектов».

**Какой инструмент выявит проблему:**
- **PMD** — правило `InsufficientStringBufferDeclaration` (или `AvoidStringBufferField` в старых версиях). Оно обнаруживает конкатенацию строк в цикле и рекомендует заменить её на `StringBuilder` или `StringBuffer`.
- **SpotBugs** — детектор `SBSC_USE_STRINGBUFFER_CONCATENATION` (String Buffer or String Builder concatenation). Он находит случаи, когда строки собираются через `+` внутри цикла, и помечает это как потенциальную проблему производительности.

**Как именно сработает проверка (на примере PMD):**
- PMD анализирует AST (абстрактное синтаксическое дерево) и ищет операторы `+` внутри циклов (`for`, `while`, `do-while`), где хотя бы один операнд является строкой.
- Если такой паттерн найден, выдаётся предупреждение с сообщением вроде: *«Avoid concatenating strings in a loop. Use a StringBuilder instead.»*

**Итог:** Некорректный пример нарушает принцип «не создавай лишние объекты», а инструменты PMD/SpotBugs легко его обнаружат на этапе статического анализа кода.
