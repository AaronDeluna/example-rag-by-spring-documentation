# Длинный список параметров

**Категория:** Стиль кодирования (Clean Code)

**Описание:** Метод принимает более 3–4 аргументов, что усложняет чтение и тестирование.

**Инструменты:** PMD, Checkstyle

---

Вот пример, демонстрирующий проблему «Длинный список параметров» и её решение с использованием паттерна «Параметризованный объект» (Parameter Object).

---

### Корректный пример

Используем класс-обёртку для группировки связанных параметров:

```java
// Класс-обёртка для параметров фильтрации
public class SearchFilter {
    private String query;
    private int minPrice;
    private int maxPrice;
    private String category;
    private boolean inStock;

    public SearchFilter(String query, int minPrice, int maxPrice, 
                        String category, boolean inStock) {
        this.query = query;
        this.minPrice = minPrice;
        this.maxPrice = maxPrice;
        this.category = category;
        this.inStock = inStock;
    }

    // геттеры (для краткости опущены)
    public String getQuery() { return query; }
    public int getMinPrice() { return minPrice; }
    public int getMaxPrice() { return maxPrice; }
    public String getCategory() { return category; }
    public boolean isInStock() { return inStock; }
}

// Класс-сервис с методом, принимающим один объект
public class ProductService {
    public List<Product> search(SearchFilter filter) {
        // ... реализация поиска
        return new ArrayList<>();
    }
}

// Использование:
SearchFilter filter = new SearchFilter("laptop", 500, 1500, "electronics", true);
ProductService service = new ProductService();
List<Product> results = service.search(filter);
```

**Почему это хорошо:**
- Метод `search` принимает только 1 аргумент.
- Параметры логически сгруппированы.
- Легко добавлять/удалять поля без изменения сигнатуры метода.
- Упрощается тестирование: можно создать фабрику тестовых фильтров.

---

### Некорректный пример

Метод с большим количеством "голых" параметров:

```java
public class ProductService {
    // Проблемный метод: 5 параметров
    public List<Product> search(String query, int minPrice, int maxPrice, 
                                String category, boolean inStock) {
        // ... реализация
        return new ArrayList<>();
    }
}

// Использование:
ProductService service = new ProductService();
List<Product> results = service.search("laptop", 500, 1500, "electronics", true);
```

**Почему это плохо:**
1. **Сложность чтения:** при вызове метода трудно понять, что означает каждый аргумент (особенно `500` и `1500` — это цена или количество?).
2. **Хрупкость:** легко перепутать порядок параметров (например, поменять местами `minPrice` и `maxPrice`).
3. **Тестирование:** для каждого теста нужно повторять длинный список аргументов, что приводит к дублированию и ошибкам.
4. **Нарушение SRP:** метод вынужден знать слишком много деталей о структуре данных.

---

### Объяснение и выявление инструментом

**Инструмент:** **PMD** (или Checkstyle с соответствующим правилом).

**Правило PMD:**  
`ExcessiveParameterList` (по умолчанию в наборе правил `java-codestyle`).

**Как сработает:**
- PMD анализирует количество формальных параметров метода.
- Если их больше порогового значения (по умолчанию 10, но можно настроить на 3-4), выдается предупреждение.
- Пример конфигурации для порога 4:
  ```xml
  <rule ref="category/java/codestyle.xml/ExcessiveParameterList">
      <properties>
          <property name="minimum" value="4" />
      </properties>
  </rule>
  ```

**Результат проверки для некорректного примера:**
```
ProductService.java:3: ExcessiveParameterList: Метод 'search' имеет 5 параметров (порог: 4).
```

**Checkstyle** имеет аналогичное правило `ParameterNumber`:
- Правило: `ParameterNumber` (модуль `Checker` → `TreeWalker`).
- По умолчанию порог — 7 параметров, но можно задать `max=4`.
- Выдаст ошибку: `More than 4 parameters (found 5).`

Оба инструмента помогут обнаружить проблему на этапе статического анализа кода.
