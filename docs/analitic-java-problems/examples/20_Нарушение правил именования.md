# Нарушение правил именования

**Категория:** Стиль кодирования (Google Java Style Guide)

**Описание:** Пакеты, классы, методы, константы названы не по стандарту (например, `userService` вместо `UserService` для класса).

**Инструменты:** Checkstyle

---

Вот пример, демонстрирующий проблему «Нарушение правил именования» для Java-кода с использованием Google Java Style Guide.

---

### Корректный пример

В этом примере соблюдены все соглашения об именовании: классы — `PascalCase`, методы и переменные — `camelCase`, константы — `UPPER_SNAKE_CASE`, пакеты — строчные буквы.

```java
package com.example.booking;

/**
 * Сервис для управления бронированиями.
 */
public class BookingService {

    public static final int MAX_BOOKINGS_PER_USER = 10;

    private final String serviceName;

    public BookingService(String serviceName) {
        this.serviceName = serviceName;
    }

    /**
     * Подтверждает бронирование для указанного пользователя.
     *
     * @param userId идентификатор пользователя
     * @return true, если бронирование успешно подтверждено
     */
    public boolean confirmBooking(Long userId) {
        if (userId == null) {
            throw new IllegalArgumentException("userId must not be null");
        }
        // логика подтверждения
        return true;
    }

    public String getServiceName() {
        return serviceName;
    }
}
```

**Почему это хорошо:**
- Класс `BookingService` — с большой буквы (PascalCase).
- Метод `confirmBooking` — с маленькой буквы (camelCase).
- Константа `MAX_BOOKINGS_PER_USER` — полностью заглавная с подчёркиваниями.
- Пакет `com.example.booking` — все буквы строчные.
- Имена осмысленны и следуют единому стилю.

---

### Некорректный пример

Демонстрирует типичные нарушения: класс назван как `userService` (должен быть `UserService`), метод `Validate_Booking` (использовано подчёркивание), константа `max_bookings_per_user` (не заглавная), пакет `com.example.Booking` (содержит заглавную букву).

```java
package com.example.Booking;

/**
 * Сервис для управления бронированиями.
 */
public class userService {              // Нарушение: класс должен быть UserService

    public static final int max_bookings_per_user = 10;  // Нарушение: константа должна быть MAX_BOOKINGS_PER_USER

    private String serviceName;

    public userService(String serviceName) {  // Нарушение: конструктор должен называться UserService
        this.serviceName = serviceName;
    }

    public boolean Validate_Booking(Long userId) {   // Нарушение: метод должен быть validateBooking (camelCase)
        if (userId == null) {
            throw new IllegalArgumentException("userId must not be null");
        }
        return true;
    }

    public String getServiceName() {
        return serviceName;
    }
}
```

---

### Объяснение и выявление инструментом

**Почему это плохо:**
- **Читаемость и предсказуемость**: Разработчики привыкли, что классы — с большой буквы, методы — с маленькой. Нарушение этих правил замедляет понимание кода и увеличивает когнитивную нагрузку.
- **Стандарты проекта**: Google Java Style Guide (и большинство корпоративных стандартов) явно требуют соблюдения этих соглашений. Их нарушение приводит к неоднородности кодовой базы.
- **Инструменты статического анализа**: Многие инструменты (Checkstyle, IntelliJ IDEA Inspections) по умолчанию настроены на проверку этих правил.

**Как инструмент (Checkstyle) обнаружит проблему:**

Checkstyle использует модули (checks), которые проверяют соответствие именования определённым регулярным выражениям. Для данного примера сработают следующие проверки:

1. **`TypeName`** (проверка имён классов и интерфейсов)  
   - Правило по умолчанию: `^[A-Z][a-zA-Z0-9]*$`  
   - Нарушение: `userService` не соответствует — начинается с маленькой буквы.  
   - Сообщение: *"Name 'userService' must match pattern '^[A-Z][a-zA-Z0-9]*$'"*

2. **`ConstantName`** (проверка имён констант)  
   - Правило по умолчанию: `^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$`  
   - Нарушение: `max_bookings_per_user` не соответствует — содержит строчные буквы.  
   - Сообщение: *"Name 'max_bookings_per_user' must match pattern '^[A-Z][A-Z0-9]*(_[A-Z0-9]+)*$'"*

3. **`MethodName`** (проверка имён методов)  
   - Правило по умолчанию: `^[a-z][a-zA-Z0-9]*$`  
   - Нарушение: `Validate_Booking` не соответствует — начинается с заглавной буквы и содержит подчёркивание.  
   - Сообщение: *"Name 'Validate_Booking' must match pattern '^[a-z][a-zA-Z0-9]*$'"*

4. **`PackageName`** (проверка имён пакетов)  
   - Правило по умолчанию: `^[a-z]+(\.[a-z][a-z0-9]*)*$`  
   - Нарушение: `com.example.Booking` содержит заглавную `B`.  
   - Сообщение: *"Name 'com.example.Booking' must match pattern '^[a-z]+(\.[a-z][a-z0-9]*)*$'"*

**Команда для запуска Checkstyle (пример):**
```bash
checkstyle -c /path/to/google_checks.xml UserService.java
```
или, если файл называется `userService.java`:
```bash
checkstyle -c /path/to/google_checks.xml userService.java
```

Checkstyle выдаст отчёт с перечислением всех строк, где нарушены правила именования, что позволяет быстро исправить код.
