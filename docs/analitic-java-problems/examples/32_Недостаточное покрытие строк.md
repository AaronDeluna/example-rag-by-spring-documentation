# Недостаточное покрытие строк

**Категория:** Покрытие кода

**Описание:** Многие строки кода не выполняются ни одним тестом.

**Инструменты:** JaCoCo, JCov, Clover

---

Вот примеры для проблемы **«Недостаточное покрытие строк»** (Line Coverage).

---

## Корректный пример

**Класс `Calculator`** содержит логику, которая полностью покрывается тестами.

```java
// Calculator.java
public class Calculator {

    public int divide(int a, int b) {
        if (b == 0) {
            throw new IllegalArgumentException("Division by zero");
        }
        return a / b;
    }

    public boolean isEven(int number) {
        return number % 2 == 0;
    }
}
```

**Тест** покрывает все строки кода (ветки `b == 0` и `b != 0`, а также метод `isEven`):

```java
// CalculatorTest.java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

public class CalculatorTest {

    @Test
    public void testDivideNormal() {
        Calculator calc = new Calculator();
        assertEquals(2, calc.divide(10, 5));
    }

    @Test
    public void testDivideByZero() {
        Calculator calc = new Calculator();
        assertThrows(IllegalArgumentException.class, () -> calc.divide(10, 0));
    }

    @Test
    public void testIsEvenTrue() {
        Calculator calc = new Calculator();
        assertTrue(calc.isEven(4));
    }

    @Test
    public void testIsEvenFalse() {
        Calculator calc = new Calculator();
        assertFalse(calc.isEven(5));
    }
}
```

**Почему это корректно:**  
Все строки кода в `Calculator` выполняются хотя бы одним тестом. Инструмент (например, JaCoCo) покажет 100% покрытие строк.

## Некорректный пример

**Класс `DiscountService`** содержит неиспользуемую логику, которая не покрыта тестами.

```java
// DiscountService.java
public class DiscountService {

    public double applyDiscount(double price, boolean isPremium) {
        double discount = 0.0;

        if (price > 100) {
            discount = 0.1;
        } else {
            discount = 0.05;  // Эта строка никогда не выполняется в тестах
        }

        if (isPremium) {
            discount += 0.05; // Эта строка никогда не выполняется в тестах
        }

        return price * (1 - discount);
    }
}
```

**Тест** покрывает только один путь:

```java
// DiscountServiceTest.java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

public class DiscountServiceTest {

    @Test
    public void testApplyDiscountHighPriceNonPremium() {
        DiscountService service = new DiscountService();
        double result = service.applyDiscount(200, false);
        assertEquals(180.0, result, 0.001);
    }
}
```

---

## Объяснение и выявление инструментом

**Почему это плохо:**
- Строки `discount = 0.05` и `discount += 0.05` никогда не выполняются. Это означает, что:
  - Ветка `else` для `price <= 100` не тестируется.
  - Ветка `isPremium == true` не тестируется.
- Если логика в этих ветках содержит ошибку (например, неправильно рассчитана скидка), она останется незамеченной.
- Снижается уверенность в корректности кода при изменении требований.

**Какой инструмент выявит проблему и как:**
- **JaCoCo** (или JCov, Clover) при запуске тестов с инструментированием сгенерирует отчёт о покрытии строк.
- В отчёте строки `discount = 0.05` и `discount += 0.05` будут отмечены **красным** (не покрыты), а строка `discount = 0.1` — зелёным (покрыта).
- Например, в JaCoCo используется **счётчик строк (Line Counter)**: для каждой строки кода подсчитывается, сколько раз она была выполнена. Если счётчик равен 0, строка считается непокрытой.
- Правило проверки: обычно в CI/CD настраивается порог (например, минимальное покрытие строк — 80%). Если порог не достигнут, сборка завершается ошибкой.
