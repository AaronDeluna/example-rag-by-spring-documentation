# Недостаточное покрытие ветвей

**Категория:** Покрытие кода

**Описание:** Не проверены логические ветви (например, все варианты `if/else`).

**Инструменты:** JaCoCo, JCov, Clover

---

Вот пример, демонстрирующий проблему недостаточного покрытия ветвей (branch coverage) и её решение.

---

### Корректный пример

**Класс с бизнес-логикой:**
```java
public class DiscountCalculator {
    public double calculateDiscount(double purchaseAmount, boolean isPremiumMember) {
        double discount;
        
        if (purchaseAmount > 100) {
            discount = isPremiumMember ? 0.20 : 0.10;
        } else {
            discount = isPremiumMember ? 0.05 : 0.0;
        }
        
        return purchaseAmount * (1 - discount);
    }
}
```

**Тест (JUnit 5), покрывающий все ветви:**
```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

public class DiscountCalculatorTest {
    private final DiscountCalculator calculator = new DiscountCalculator();

    @Test
    public void testAllBranches() {
        // Ветвь purchaseAmount > 100 и isPremiumMember = true
        assertEquals(80.0, calculator.calculateDiscount(100.0, true), 0.001);
        
        // Ветвь purchaseAmount > 100 и isPremiumMember = false
        assertEquals(90.0, calculator.calculateDiscount(100.0, false), 0.001);
        
        // Ветвь purchaseAmount <= 100 и isPremiumMember = true
        assertEquals(95.0, calculator.calculateDiscount(100.0, true), 0.001);
        
        // Ветвь purchaseAmount <= 100 и isPremiumMember = false
        assertEquals(100.0, calculator.calculateDiscount(100.0, false), 0.001);
    }
}
```

**Почему это корректно:**
- Тест проверяет все 4 возможные комбинации условий: `(purchaseAmount > 100, isPremiumMember) → (true,true), (true,false), (false,true), (false,false)`.
- Достигнуто 100% покрытие ветвей.

### Некорректный пример

**Тот же класс (логика не меняется):**
```java
public class DiscountCalculator {
    public double calculateDiscount(double purchaseAmount, boolean isPremiumMember) {
        double discount;
        
        if (purchaseAmount > 100) {
            discount = isPremiumMember ? 0.20 : 0.10;
        } else {
            discount = isPremiumMember ? 0.05 : 0.0;
        }
        
        return purchaseAmount * (1 - discount);
    }
}
```

**Неполный тест:**
```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.assertEquals;

public class DiscountCalculatorTest {
    private final DiscountCalculator calculator = new DiscountCalculator();

    @Test
    public void testOnlyOneBranch() {
        // Проверяем только случай purchaseAmount > 100 и isPremiumMember = true
        assertEquals(80.0, calculator.calculateDiscount(100.0, true), 0.001);
        
        // Проверяем только случай purchaseAmount <= 100 и isPremiumMember = false
        assertEquals(100.0, calculator.calculateDiscount(100.0, false), 0.001);
    }
}
```

---

### Объяснение и выявление инструментом

**Почему это плохо:**
- В тесте проверены только 2 из 4 возможных комбинаций условий.
- Остаются непроверенными ветви:
  - `purchaseAmount > 100` + `isPremiumMember = false` (должен примениться дисконт 10%)
  - `purchaseAmount <= 100` + `isPremiumMember = true` (должен примениться дисконт 5%)
- Если в этих ветвях есть ошибка (например, перепутаны проценты), тест её не обнаружит.

**Какой инструмент выявит проблему:**
- **JaCoCo** (или аналоги: JCov, Clover) при анализе покрытия кода покажет, что покрытие ветвей (branch coverage) составляет 50% (2 из 4 ветвей).

**Конкретная проверка (на примере JaCoCo):**
1. Запустите тесты с плагином JaCoCo (например, в Maven: `mvn test jacoco:report`).
2. В отчёте JaCoCo для метода `calculateDiscount` будет отображено:
   - Счётчик ветвей: `2 of 4 branches missed` (2 непокрытые ветви).
   - Красным цветом будут выделены строки с условными операторами, где не все ветви проверены.
3. Правило (rule) в JaCoCo, которое можно настроить для автоматической проверки:
   ```xml
   <rule>
       <element>METHOD</element>
       <limits>
           <limit>
               <counter>BRANCH</counter>
               <value>COVEREDRATIO</value>
               <minimum>1.0</minimum> <!-- Требуем 100% покрытия ветвей -->
           </limit>
       </limits>
   </rule>
   ```
   При нарушении сборка будет прервана с сообщением: `Rule violated for method calculateDiscount: branch coverage ratio is 0.5, but expected minimum is 1.0`.

**Итог:** JaCoCo (и другие инструменты покрытия) детектируют проблему, показывая, что не все логические ветви `if/else` и тернарных операторов проверены тестами.
