# Нарушение форматирования

**Категория:** Стиль кодирования (Google Java Style Guide)

**Описание:** Неправильные отступы, длина строки >100 символов, нарушение порядка импортов.

**Инструменты:** Checkstyle

---

Вот примеры корректного и некорректного кода на Java для проблемы «Нарушение форматирования» (отступы, длина строки, порядок импортов).

---

### Корректный пример

```java
import java.util.ArrayList;
import java.util.List;

/**
 * Пример класса, соблюдающего Google Java Style Guide.
 */
public class CorrectFormatting {

    private List<String> items;

    public CorrectFormatting() {
        items = new ArrayList<>();
    }

    public void addItem(String item) {
        if (item != null && !item.isEmpty()) {
            items.add(item);
        }
    }

    public String getConcatenatedItems() {
        StringBuilder sb = new StringBuilder();
        for (String item : items) {
            sb.append(item);
            sb.append(", ");
        }
        // Длина строки не превышает 100 символов
        return sb.length() > 0 ? sb.substring(0, sb.length() - 2) : "";
    }
}
```

**Почему это корректно:**
- Импорты расположены в алфавитном порядке.
- Отступы — 2 пробела (как требует Google Style Guide), без табуляций.
- Строки короче 100 символов.
- Класс и методы имеют понятные имена.

### Некорректный пример

```java
import java.util.List;
import java.util.ArrayList;

public class BadFormatting {

private List<String> items;

public BadFormatting() {
items = new ArrayList<>();
}

public void addItem(String item) {
if (item != null && !item.isEmpty()) {
items.add(item);
}
}

public String getConcatenatedItems() {
StringBuilder sb = new StringBuilder();
for (String item : items) {
sb.append(item);
sb.append(", ");
}
return sb.length() > 0 ? sb.substring(0, sb.length() - 2) : "";
}
}
```

**Проблемы:**
1. **Порядок импортов** нарушен: `List` идёт после `ArrayList`, хотя по алфавиту должно быть наоборот (`ArrayList` → `List`).
2. **Отступы** отсутствуют: все строки начинаются с нулевого отступа (даже тело класса и методы).
3. **Длина строки** может превышать 100 символов (например, строка с `sb.substring(0, sb.length() - 2)` — в реальном коде может быть ещё длиннее, но здесь проблема именно в отступах).

---

### Объяснение и выявление инструментом

**Почему это плохо:**
- Нарушение единого стиля делает код трудночитаемым и не поддерживаемым.
- Отсутствие отступов скрывает логическую структуру программы.
- Неправильный порядок импортов может вызвать конфликты при автоматическом слиянии кода.

**Какой инструмент выявит и какое правило:**
- **Checkstyle** с конфигурацией Google Java Style Guide.
- **Правила, которые сработают:**
  - `Indentation` (проверка отступов) — обнаружит отсутствие отступов в теле класса/методов.
  - `CustomImportOrder` (порядок импортов) — найдёт, что `ArrayList` идёт после `List`, хотя должен быть перед ним.
  - `LineLength` (максимальная длина строки) — если строка превышает 100 символов, будет зафиксировано нарушение.

**Пример вывода Checkstyle:**
```
BadFormatting.java:2: 'import' must be before 'import' in the same group. (CustomImportOrder)
BadFormatting.java:4: 'method def modifier' has incorrect indentation level 0, expected level 2. (Indentation)
BadFormatting.java:7: 'method def' child has incorrect indentation level 0, expected level 4. (Indentation)
```
