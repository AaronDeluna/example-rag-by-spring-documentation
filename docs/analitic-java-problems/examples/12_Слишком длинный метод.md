# Слишком длинный метод

**Категория:** Стиль кодирования (Clean Code)

**Описание:** Метод содержит более 20–30 строк, делает много разных вещей.

**Инструменты:** PMD, Checkstyle, SpotBugs

---

Вот пример для проблемы **«Слишком длинный метод»** в Java, соответствующий вашим требованиям.

---

### Корректный пример

Код разбит на небольшие, сфокусированные методы (менее 20 строк каждый), каждый из которых выполняет одну задачу.

```java
import java.util.List;

public class OrderProcessor {

    public void processOrders(List<Order> orders) {
        for (Order order : orders) {
            validateOrder(order);
            calculateTotal(order);
            applyDiscount(order);
            saveOrder(order);
        }
    }

    private void validateOrder(Order order) {
        if (order.getItems().isEmpty()) {
            throw new IllegalArgumentException("Order must have at least one item");
        }
        if (order.getCustomer() == null) {
            throw new IllegalArgumentException("Customer is required");
        }
    }

    private void calculateTotal(Order order) {
        double total = 0;
        for (Item item : order.getItems()) {
            total += item.getPrice() * item.getQuantity();
        }
        order.setTotal(total);
    }

    private void applyDiscount(Order order) {
        if (order.getTotal() > 1000) {
            order.setTotal(order.getTotal() * 0.9); // 10% discount
        }
    }

    private void saveOrder(Order order) {
        // Имитация сохранения в БД
        System.out.println("Order saved: " + order.getId());
    }
}

// Вспомогательные классы (упрощённые)
class Order {
    private String id;
    private List<Item> items;
    private Customer customer;
    private double total;

    // геттеры/сеттеры (опущены для краткости)
}

class Item {
    private double price;
    private int quantity;
    // геттеры/сеттеры
}

class Customer {
    private String name;
    // геттеры/сеттеры
}
```

### Некорректный пример

Один метод делает всё: валидацию, расчёт, применение скидки и сохранение — более 30 строк, нарушает принцип единственной ответственности.

```java
import java.util.List;

public class OrderProcessor {

    public void processOrders(List<Order> orders) {
        for (Order order : orders) {
            // Валидация
            if (order.getItems().isEmpty()) {
                throw new IllegalArgumentException("Order must have at least one item");
            }
            if (order.getCustomer() == null) {
                throw new IllegalArgumentException("Customer is required");
            }

            // Расчёт суммы
            double total = 0;
            for (Item item : order.getItems()) {
                total += item.getPrice() * item.getQuantity();
            }

            // Применение скидки
            if (total > 1000) {
                total = total * 0.9;
            }

            // Сохранение
            order.setTotal(total);
            System.out.println("Order saved: " + order.getId());

            // Дополнительная логика (увеличивает длину)
            sendConfirmationEmail(order);
            updateInventory(order);
            logProcessing(order);
        }
    }

    private void sendConfirmationEmail(Order order) {
        // 10 строк для отправки email
    }

    private void updateInventory(Order order) {
        // 10 строк для обновления склада
    }

    private void logProcessing(Order order) {
        // 5 строк для логирования
    }
}
```

### Объяснение и выявление инструментом

**Почему некорректный пример плох:**

- Метод `processOrders` содержит **более 30 строк** (с учётом вложенных блоков и комментариев).
- Он делает **много разных вещей**: валидацию, расчёт суммы, применение скидки, сохранение, отправку email, обновление склада, логирование.
- **Нарушение SRP (Single Responsibility Principle)** — метод отвечает за несколько несвязанных операций.
- **Сложность понимания и тестирования** — чтобы протестировать расчёт, нужно выполнить весь метод, включая побочные эффекты (email, склад).

**Какой инструмент выявит и какое правило сработает:**

- **PMD** — правило `ExcessiveMethodLength` (по умолчанию порог 100 строк, но можно настроить на 20-30).  
  *Пример конфигурации:* `<rule ref="category/java/design.xml/ExcessiveMethodLength"><properties><property name="minimum" value="20"/></properties></rule>`
- **Checkstyle** — правило `MethodLength` (по умолчанию 150 строк, но настраивается).  
  *Конфигурация:* `<module name="MethodLength"><property name="max" value="20"/></module>`
- **SpotBugs** — не имеет прямого правила для длины метода, но может выявить косвенные признаки (например, `SCA_SUSPICIOUS_CLASS_INNER`), если метод нарушает другие правила.

**Как именно сработает:**  
При запуске анализа PMD или Checkstyle для некорректного примера будет выдано предупреждение:  
*"The method 'processOrders' has a length of 38 lines (including comments). Maximum allowed is 20."*
