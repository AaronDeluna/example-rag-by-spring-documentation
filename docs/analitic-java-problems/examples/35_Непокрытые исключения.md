# Непокрытые исключения

**Категория:** Покрытие кода

**Описание:** В коде есть блоки `catch`, которые не покрываются тестами, что может скрывать ошибки.

**Инструменты:** JaCoCo, JCov, Clover

---

Вот примеры, иллюстрирующие проблему «Непокрытые исключения» в Java.

---

### Корректный пример

В этом примере каждый блок `catch` покрыт тестами: тест проверяет как успешный сценарий, так и сценарий с исключением.

**Класс с бизнес-логикой (Calculator.java):**
```java
public class Calculator {
    public int divide(int a, int b) {
        try {
            return a / b;
        } catch (ArithmeticException e) {
            // Логируем и пробрасываем дальше или обрабатываем
            throw new IllegalArgumentException("Деление на ноль", e);
        }
    }
}
```

**Тест (CalculatorTest.java):**
```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class CalculatorTest {

    @Test
    void testDivideSuccess() {
        Calculator calc = new Calculator();
        assertEquals(2, calc.divide(10, 5));
    }

    @Test
    void testDivideByZero() {
        Calculator calc = new Calculator();
        Exception exception = assertThrows(IllegalArgumentException.class, () -> {
            calc.divide(10, 0);
        });
        assertTrue(exception.getMessage().contains("Деление на ноль"));
    }
}
```

**Почему это корректно:**  
- Блок `catch` явно обрабатывает исключение (пробрасывает с осмысленным сообщением).  
- Тест `testDivideByZero` проверяет, что именно этот блок `catch` выполняется.  
- Покрытие кода (например, JaCoCo) покажет 100% покрытие для метода `divide`.

### Некорректный пример

**Класс с бизнес-логикой (UserService.java):**
```java
import java.io.*;

public class UserService {
    public String loadUserName(String path) {
        String name = "";
        try (BufferedReader reader = new BufferedReader(new FileReader(path))) {
            name = reader.readLine();
        } catch (IOException e) {
            // Пустой catch — просто игнорируем ошибку
            // Никакой обработки, логирования или проброса
        }
        return name;
    }
}
```

**Тест (UserServiceTest.java):**
```java
import org.junit.jupiter.api.Test;
import static org.junit.jupiter.api.Assertions.*;

class UserServiceTest {

    @Test
    void testLoadUserNameSuccess() {
        UserService service = new UserService();
        // Предположим, что файл существует и содержит "John"
        String result = service.loadUserName("valid_user.txt");
        assertEquals("John", result);
    }
    // Нет теста на случай, когда файл не существует или происходит другая IOException
}
```

**Проблема:**  
- Блок `catch (IOException e)` пустой — исключение молча проглатывается.  
- В тестах нет сценария, который вызывает это исключение (например, передача несуществующего файла).  
- Если в будущем в блок `catch` добавится важная логика (логирование, восстановление), она останется непроверенной.

### Объяснение и выявление инструментом

**Почему это плохо:**  
- Пустой `catch` скрывает ошибки ввода-вывода, что может привести к неожиданному поведению программы.  
- Отсутствие теста на исключение означает, что блок кода внутри `catch` никогда не выполняется в тестовом окружении.  
- Это создаёт «мёртвый код» (uncovered code) и снижает надёжность приложения.

**Какой инструмент выявит:**  
- **JaCoCo** (или аналоги: JCov, Clover)  
- **Конкретная проверка:** Анализ покрытия строк (line coverage) покажет, что строка `catch (IOException e) { ... }` не отмечена как выполненная (красный цвет в отчёте).  
- **Правило:** JaCoCo по умолчанию считает непокрытыми все строки, которые не были задействованы ни в одном тесте. В данном случае строка с открывающей скобкой `{` и строка с закрывающей `}` (если внутри пусто) останутся непокрытыми.  
- **Дополнительно:** Можно настроить проверку минимального порога покрытия (например, `<limit><counter>LINE</counter><value>COVEREDRATIO</value><minimum>0.8</minimum></limit>` в Maven/Gradle), и сборка упадёт, если блок `catch` не покрыт.

**Как это выглядит в отчёте JaCoCo:**  
- В HTML-отчёте строка с `catch (IOException e) {` будет выделена красным (не покрыта).  
- Если внутри блока есть код, он тоже будет красным.  
- Счётчик инструкций (instruction coverage) покажет 0% для этого блока.
